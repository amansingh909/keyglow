# Keyglow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Layered keyboard lighting for a Razer BlackWidow V3 Tenkeyless on Linux: a tiny background program draws the frames, and a settings window edits the layers.

**Architecture:** A Rust workspace with three crates. `keyglow-core` holds the settings model, effects, mixing, key map, frame encoding, preset import and the settings files. `keyglowd` reads key presses and the settings file and writes frames to the OpenRazer driver's sysfs files. `keyglow` is an egui window that only edits the settings file.

**Tech Stack:** Rust 1.99 (`~/.cargo/bin`, put it on PATH with `export PATH=$HOME/.cargo/bin:$PATH`), serde + serde_json, inotify, nix, zip, quick-xml, eframe/egui 0.37, rfd.

**Spec:** `docs/superpowers/specs/2026-10-22-keyglow-design.md`

## Global Constraints

- Keyboard only: USB 1532:0A24, grid of 6 rows by 18 columns (`ROWS = 6`, `COLS = 18`). Column 0 has no keys.
- Frame bytes: for each row r in 0..6: `[r, 0, 17]` followed by 18 RGB triples. 342 bytes per frame, written in one write to `matrix_custom_frame`, then `b"1"` written to `matrix_effect_custom`.
- The lighting interface is the `razerkbd` HID device directory under `/sys/bus/hid/drivers/razerkbd/` whose name contains `:1532:0A24.` and which contains `matrix_custom_frame`.
- Key presses: `/dev/input/by-id/` entries whose names contain `Razer_BlackWidow_V3_Tenkeyless` and end with `event-kbd`. Read, never grab.
- Settings: `~/.config/keyglow/active.json` (or `$XDG_CONFIG_HOME/keyglow`), saved setups in `setups/<name>.json`, written atomically (temp file then rename). Status: `$XDG_RUNTIME_DIR/keyglow/status.json`.
- Layers are stored bottom first (`layers[0]` is the bottom). The window shows them top first.
- Frame rate default 30, clamped to 10..=60. Brightness 0..=100. Opacity 0..=100. Speed sliders 1..=100.
- Owner default setup, named "Default": Wave (`#03FFFA`, `#55007F`, speed 40, direction 0 degrees, band 18), Starlight (random, density 30, 1200 ms), Ripple (`#FFFFFF`, speed 50, reach 12, thickness 1.5), all enabled at opacity 100.
- Background program weight: no polling; sleep on fds or the next frame time; no frames while nothing moves; about 3% of one core at 30 fps; under 20 MB resident.
- Privacy: key codes are used only to find a grid position. Never log, print or store key codes or typed text.
- Tests never touch `/sys`, `/dev/input`, `~/.config/keyglow` or `$XDG_RUNTIME_DIR/keyglow`; they use temp dirs. Nobody runs `keyglowd` against the real device except the controller.
- Docs and commit messages: plain English, no em or en dashes, no Claude attribution or Co-Authored-By lines.
- Build at low priority: `nice -n 10 cargo ...` with `CARGO_BUILD_JOBS=4`.

## Review Focus

1. A settings file edited by hand with out-of-range or missing values (fps 0, opacity 300, empty colour list): the daemon must clamp and keep running, and keep the last good setup on a parse error.
2. The keyboard unplugged and replugged, or the machine suspended: writes fail, the daemon must drop the device, rescan every 2 seconds, and resume drawing without restarting.
3. A hostile or broken `.ChromaEffects` file (huge XML, zip bomb, not a zip, odd colours): import must fail cleanly with a message, never panic or write files.
4. Idle cost: a setup with only Static layers and no key presses must draw one frame and then sleep (apart from the 5 second resend), not tick at the frame rate.
5. Two quick saves from the window while the daemon reads: the daemon must never read a half-written file (atomic rename) and must pick up the last one.

### Task 2: Effects and layer mixing

**Files:**
- Modify: `crates/keyglow-core/src/engine.rs` (and `src/effects/*.rs` if it grows; one file per effect is fine)

**Interfaces:**
- Consumes: everything from Task 1.
- Produces: `engine::Engine` with
  - `Engine::new(setup: Setup, seed: u64) -> Engine` (setup is passed through `sanitized()`)
  - `set_setup(&mut self, setup: Setup)` (replaces layers; clears running ripples and stars)
  - `key_press(&mut self, row: usize, col: usize, t: f64)` (t is seconds on a monotonic clock)
  - `render(&mut self, t: f64) -> Frame` (brightness applied)
  - `animating(&self, t: f64) -> bool`: true if any enabled layer is Breathing, Spectrum, Wave, Wheel, Starlight or Fire, or a Reactive or Ripple effect is still fading at `t`
  - `fps(&self) -> u32`

Behaviour (spec "Effects and their settings"): mixing starts from black and goes bottom to top; each layer gives each key a colour and a coverage between 0 and 1, and the key becomes `lerp(below, colour, coverage * opacity / 100)`. Static, Breathing, Spectrum, Wave, Wheel and Fire cover every key fully; Starlight, Reactive and Ripple cover only keys they are lighting. Speed maps to a rate with `rate(speed) = 0.05 * 20f32.powf((speed - 1) / 99)` cycles per second (speed 1 is one cycle in 20 s, speed 100 one per second). Ripple ring speed is `rate(speed) * 40` keys per second. Starlight spawns `density / 100 * 20` stars per second on keys where `has_led`, each fading in and out over `duration_ms`. Random palettes use `hsv(rng, 1, 1)`. Positions come from `keymap::key_position`.

### Task 3: Razer preset import

**Files:**
- Modify: `crates/keyglow-core/src/preset.rs`, `crates/keyglow-core/Cargo.toml` (zip, quick-xml)
- Create: `crates/keyglow-core/tests/fixtures/sample.xml` (copy given in the brief)

**Interfaces:**
- Consumes: Task 1 model.
- Produces: `preset::Imported { setup: Setup, skipped: Vec<String>, notes: Vec<String> }`, `preset::PresetError` (`NotAZip`, `NoXml`, `TooLarge`, `BadXml(String)`) with `Display`, and `preset::import(bytes: &[u8], name_hint: &str) -> Result<Imported, PresetError>`.

Rules: refuse input over 5 MB and an XML entry over 2 MB (check the declared size and also stop reading past the limit); read only the first entry ending in `.xml`, in memory; never write files. Layer order is the XML order (bottom first). `Visible` gives `enabled`, `Alpha` gives `opacity`. Colours come from `RzColor` (missing Red, Green or Blue means 0); `RandomColor` true at the top level or no colours gives a random palette where the effect allows it. Mapping: static, breathing, spectrum, wave (rainbow when it has no colours), wheel, starlight (`Duration` short/medium/long to 600/1200/2400 ms; `Density` 1 to 5 to density 15, 30, 50, 70, 90), reactive, ripple (`Width` over 25, clamped, to `reach`), fire. Map Razer `Speed` (1 to 30 or so) to Keyglow speed with a clamp to 1..=100 (builder's call, documented in a comment). Anything else is skipped and its Razer name recorded in `skipped`. Key-press layers: `Start` of `onkeypress` on static or breathing becomes Reactive in that colour (with a note); on any effect other than ripple and reactive it is skipped (recorded in `skipped` as e.g. `wave (on key press)`). Regions: count each layer's `DeviceCell` entries; a layer with fewer cells than the largest layer is imported over the whole keyboard and noted in `notes` (e.g. `Static covered part of the keyboard; here it covers all of it`). `End`, `Cycle` and `Pause` are ignored. The setup name is the `Name` element directly under `LightingEffects` (not device or layer names), or `name_hint` without its extension.

### Task 4: The background program (`keyglowd`)

**Files:**
- Create: `crates/keyglowd/src/{main.rs, device.rs, input.rs, watch.rs, run.rs}`
- Test: unit tests in modules, plus `crates/keyglowd/tests/fake_device.rs`

**Interfaces:**
- Consumes: `Engine`, `Store`, `Status`, `write_status`, `status_path`, `grid_of_keycode`, `frame::encode`.
- Produces: the `keyglowd` binary with options `--config-dir DIR`, `--sysfs-dir DIR` (default `/sys/bus/hid/drivers/razerkbd`), `--input-dir DIR` (default `/dev/input/by-id`), `--status-file PATH` (default `store::status_path()`). Test hooks are these options only.
  - `device::find(sysfs_dir: &Path) -> Option<PathBuf>`; `device::Keyboard::open(dir) -> io::Result<Keyboard>` keeping both files open; `Keyboard::show(&mut self, bytes: &[u8]) -> io::Result<()>` (pwrite at offset 0 to `matrix_custom_frame`, then `b"1"` to `matrix_effect_custom`).
  - `input::find(input_dir: &Path) -> Vec<PathBuf>`; `input::parse(buf: &[u8]) -> Vec<u16>` returning key codes of `EV_KEY` events with value 1 from 24-byte `input_event` records (x86_64 layout: 16 bytes time, u16 type, u16 code, i32 value).
  - `run::next_wait(animating: bool, keyboard: bool, dimmed: bool, since_last_frame: Duration, frame_interval: Duration) -> Duration`: no keyboard gives 2 s (rescan); dimmed gives 2 s (brightness check); animating gives the time left to the next frame; still gives the time left to a 5 s resend. Never zero unless a frame is overdue.
  - `device::Keyboard::brightness(&mut self) -> io::Result<u8>` reading `matrix_brightness` (text, 0 to 255).

Loop: `poll` (nix) on the key event fds, an inotify fd watching the config dir (`CLOSE_WRITE | MOVED_TO`, reacting to `active.json`), and a signalfd for SIGTERM and SIGINT, with the timeout from `next_wait`. On a config event, reload with `Store::load_active`; on error keep the current setup and put the error in the status detail. On a key press, map with `grid_of_keycode` and call `engine.key_press`. Draw when the engine is animating and the frame is due, right after any change (setup, key press), and on the 5 s resend. Every 2 s while it would be drawing, read the brightness; while it reads 0 (OpenRazer dims the keyboard when the screen saver starts) draw nothing and ignore key presses, and when it comes back draw at once. Never write `matrix_brightness`. On a write error, drop the keyboard and rescan every 2 s; reopen key event files on rescan too. Write the status file when the keyboard appears or disappears and at start; remove nothing on exit. Use `CLOCK_MONOTONIC` (`std::time::Instant`). Log only start, keyboard found or lost, and settings reload failures to stderr; never key codes.

### Task 5: The settings window (`keyglow`)

**Files:**
- Create: `crates/keyglow/src/{main.rs, app.rs, model.rs, editors.rs}`

**Interfaces:**
- Consumes: `Setup`, `Layer`, `Effect`, `EffectKind`, `Palette`, `Store`, `read_status`, `status_path`, `preset::import`.
- Produces: the `keyglow` binary, plus `model.rs` functions that hold every non-drawing rule:
  - `add_layer(setup: &mut Setup, kind: EffectKind) -> usize` (adds on top, returns its index), `delete_layer(setup, index)`, `move_up(setup, index) -> usize` and `move_down(setup, index) -> usize` (in screen terms: up means towards the top of the stack, clamped), `display_order(setup) -> Vec<usize>` (indexes top first).
  - `SaveThrottle { min_gap: Duration }` with `should_save(&mut self, now: Instant, dirty: bool) -> bool` (save at most every 50 ms while dragging, and always once after the last change).
  - `daemon_state(status: Option<Status>, pid_alive: impl Fn(u32) -> bool) -> DaemonState` (`NotRunning`, `NoKeyboard`, `Ready`).
  - `is_unsaved(active: &Setup, saved: Option<&Setup>) -> bool` (true when there is no saved setup of that name or it differs).

Window (spec "The settings window"): left panel lists layers top first with an on/off checkbox each, selection, buttons Add (menu of `EffectKind::ALL` labels), Delete, Up, Down. Right panel edits the selected layer: opacity slider, then the effect's fields with egui widgets (`color_edit_button_srgb` for colours, add and remove colour buttons for palettes, a Random/Rainbow/Colours choice where the effect allows, sliders for speed, density, duration, reach, thickness, height, band; direction as a slider in degrees plus Left, Right, Up, Down buttons; clockwise checkbox).
